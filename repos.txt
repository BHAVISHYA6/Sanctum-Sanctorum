SANCTUM SANCTORUM ASSIGNMENT - SIMPLE FEATURE SUMMARY

What this assignment is about
------------------------------
This is a members-only bookstore and lending library. Members can buy books,
borrow books, and view reports about the store.

The original project was partly finished. Some basic code existed, but many
required features were missing or returned errors. The task was to finish the
backend according to SPEC.md and make the tests pass.

Old features and problems
-------------------------
- Books existed, but ISBN checksum validation was incomplete.
- Duplicate ISBNs could expose a database error instead of a clear 409 response.
- Book PATCH updates were missing.
- Book search, filters, sorting, and pagination were incomplete.
- Member email cleanup and duplicate-email handling were incomplete.
- Member statistics were not fully implemented.
- Creating orders returned 501 and order rules were incomplete.
- Creating loans returned 501 and loan fields and rules were incomplete.
- The top-books report returned 501.
- Many tests failed because these features were unfinished.

Updated features now
--------------------
Books:
- Titles and authors are cleaned and validated.
- ISBN spaces and hyphens are removed and ISBN-13 check digits are validated.
- Duplicate ISBNs are rejected clearly.
- Books support partial PATCH updates.
- Books support search, restricted filtering, price filtering, sorting, and pagination.

Members:
- Names and emails are cleaned before saving.
- Emails are converted to lowercase and duplicates are rejected.
- Member tiers are checked.
- Orders and member statistics can be viewed.

Orders:
- Members, books, quantities, and duplicate items are validated.
- Restricted-book access rules are enforced.
- Stock is checked before changes, so failed orders do not partially change stock.
- Tier and bulk discounts are calculated.
- Prices are saved at purchase time.
- Orders can be paid or cancelled, and cancellation restores stock.

Loans:
- Borrowing checks member access, tier limits, overdue loans, duplicate loans,
  and available stock.
- Stock decreases on borrowing and returns on return.
- Loan status can be active, overdue, or returned.
- Late fees are calculated for overdue returns and capped at book price.

Reports:
- The top-books report works.
- Only paid orders count as sales.
- Quantities are combined and results are sorted and limited correctly.

Application and deployment:
- FastAPI provides the API, `/health`, and `/docs`.
- The static frontend is served from `/` and uses the same API.
- PostgreSQL is supported through `SANCTUM_DATABASE_URL`.
- SQLite remains available for local development.
- The application is deployed at https://sanctum-sanctorum-gilt.vercel.app/

Testing status
--------------
The focused tests for books, loans, members, orders, and reports pass. The
repository notes record a full PostgreSQL-configured result of 202 tests passed.

In simple terms, the old project was a partially built bookstore API. The
updated project now has the required bookstore, member, order, loan, report,
frontend, database, and deployment functionality.
